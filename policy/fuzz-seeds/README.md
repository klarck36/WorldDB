# Fuzz seed corpora

These small, synthetic inputs are checked-in seeds for the M9-04 parser inventory. Text and JSON
files contain one input per file. Files ending in `.hex` contain raw bytes encoded as lowercase
hex; the campaign harness decodes them before invoking the parser. Larger binary seeds are the
versioned M7-16h fixture files referenced directly by `policy/fuzz-targets.tsv`.

The seed files are input data, not source-code hints. Mutation strategies are separately listed in
`policy/decoder-seeds.tsv`. The migration-run-journal fixture is checked against the deterministic
seed generated by the core decoder harness. Adapter `.hex` seeds are canonical frames emitted by
the adapter protocol encoders; storage index, pin, upgrade-journal, and engine job-journal seeds
preserve their binary or checksum envelope formats. The query-cursor text corpus includes one
fixed-size versioned token and one malformed token.
The logical-import-plan seed is a canonical digest-protected plan bound to the
versioned logical-export fixture; desktop export/import and purge seeds include
valid DTO/report examples alongside malformed inputs.
